Повторное применение после обновления
Сначала восстановить/проверить публичный транспорт и его сертификат по
PUBLIC-SIP.txt, а также модуль RtpSourceReset по recovery/2026-11-14/RESTORE.txt.
Сравнить действующие файлы, сохранить копии, установить два конфигурационных
файла из linphone-push/config/ в /etc/asterisk (root:asterisk, 0640).
Добавить по одному include, если отсутствуют:
  В pjsip.conf: #include pjsip_linphone_federation.conf
  В extensions.conf: #include extensions_linphone_federation.conf
Убедиться, что 613 не назначен другому маршруту. Выполнить:
  asterisk -rx 'module reload res_pjsip.so'
  asterisk -rx 'dialplan reload'
Проверить endpoint linphone-federation (пустые outbound_auth/outbound_proxy),
613@from-direct-ip-phone, TLS/SRTP, Caller ID и речь контрольным разговором.
При новом ABI сначала пересобрать RtpSourceReset; старый .so не копировать
вслепую. Учётные данные Linphone для этого маршрута не требуются.

Откат только теста: при отсутствии активного тестового звонка удалить
два новых include и два новых файла, затем module reload res_pjsip.so
и dialplan reload. Не восстанавливать весь базовый файл поверх более
поздних правок; сначала сравнить. Рабочий 612 и прежний auth не удалять.
