Домашняя израильская SIM для поездок — 14 ноября 2026

Целевая схема
Входящий: звонящий -> домашний iPhone/SIM -> Bluetooth -> Asterisk .128 ->
Linphone traveler-example@sip.linphone.org по TLS/SRTP. Стационарный не вызывается:
пользователь сообщил, что он нужен был только для отладки.
Исходящий: Linphone, линия «Домашняя SIM» (1003 на собственном Asterisk) ->
TLS/SRTP -> Asterisk -> Bluetooth -> домашний iPhone/SIM -> израильский номер.
Учётка sip.linphone.org используется самим приложением для приёма/push;
Asterisk больше не загружает её auth и не использует её для отправки.

Состояние
Обе цепочки проверены 14 ноября 2026 из внешней сети. Пользователь
подтвердил речь в обе стороны, правильный номер и завершение вызовов.
Пользователь добавил линию 1003; регистрация по TLS подтверждена на сервере.
До этого прямой вызов от домена АТС в Linphone подтверждён отдельно:
LINPHONE-FEDERATION.txt. Это не заменяет проверку с домашней SIM.

Настройка приложения
Сохранить аккаунт traveler-example@sip.linphone.org для входящих/push.
Добавить сторонний SIP-аккаунт:
  имя пользователя и auth username: 1003;
  домен: home.example.net; порт TLS 5061 по умолчанию;
  транспорт TLS; шифрование SRTP обязательно;
  отображаемое имя «Домашняя SIM».
Пароль показан локально roaming/show-client-settings.py, в переписке отсутствует.
Он сохранён в Secret Service: host=home.example.net, username=1003,
kind=travel-sip, service=asterisk-gateway. На сервере — отдельный защищённый
/etc/asterisk/pjsip_roaming_auth.conf. Не путать с паролем сервиса Linphone.
Для исходящих выбирать линию «Домашняя SIM»; входящие идут на прежний аккаунт.

Набор
Поддерживаются обычные 0... израильские стационарные/мобильные, +972...,
00972...; международные формы нормализуются в местный набор через SIM.
Также допускаются национальные короткие номера 1XX/1XXX, сервисные
10-значные номера 1... и звёздочные * с 3–6 цифрами. Реальная доступность
конкретной службы определяется оператором SIM. Международные направления
в других странах не включены. Вызовы экстренных служб не тестировались.
600 на линии 1003 — эхо-тест без обращения к SIM.
612 и 613 на отладочном стационарном теперь оба используют маршрут без auth.

Доступ
Отдельный endpoint 1003 с обязательной SIP-авторизацией на нашей АТС,
контекст from-travel-phone. Перед использованием SIM проверяется TLS
и локальный адрес приёма 192.168.50.10:5062, затем формат номера.
Публичный контекст from-public-sip по-прежнему не содержит сотовых маршрутов.
Идентификатор отправителя сам по себе не даёт право на платный вызов.
3 внешние попытки без авторизации получили 401, в сотовую сеть не вышли.
14 проверок форматов номеров выполнены штатной REGEX-функцией Asterisk.
Доказательства: diagnostics/2026-11-14-roaming/access-check.jsonl,
number-validation.json, install.json.

Файлы
roaming/config/pjsip_roaming.conf и extensions_roaming.conf — новые настройки.
На сервере они находятся в /etc/asterisk, включены из pjsip.conf/extensions.conf.
Из pjsip.conf исключены pjsip_linphone_push.conf и pjsip_linphone_push_auth.conf;
прежние защищённые файлы сохранены, но объекты linphone-push и его auth
выгружены. Исходящие маршруты 612 также переведены на linphone-federation.
Входящий from-home-mobile вызывает только linphone-cellular; у него From
строится из номера реального звонящего и нашего домена. RtpSourceReset
применяется к SIP-плечу. Caller ID полного маршрута ещё требует проверки.
Изменения применены без перезапуска Asterisk/сервера или соседних служб.

Восстановление и откат
Резервная копия изменённых базовых файлов на .128:
/var/backups/asterisk-roaming/20261114-193544/.
Перед восстановлением сохранить действующие файлы, сравнить новые изменения,
не копировать архив вслепую поверх конфигурации. Сначала восстановить
публичный TLS, сертификат, NAT и RTP по PUBLIC-SIP.txt, модули по
recovery/2026-11-14/RESTORE.txt. Затем применить маршруты roaming, сохранив
актуальный секрет 1003 из защищённого файла или связки ключей.
roaming/deploy.py — одноразовый установщик: повторная установка блокируется.
Откат: при отсутствии разговоров вернуть только изменённые участки из
резервной копии, удалить новые include и файлы roaming, перечитать PJSIP
и dialplan. Возврат старых include снова включает авторизацию Linphone;
делать это только при сознательном откате всей схемы. Пароль T780P не менять.

Уточнение после первой попытки исходящего
Пользователь подтвердил подключение 1003; сервер видел регистрацию по TLS.
Первый вызов отклонён 488 ещё до набора SIM: сторонняя учётка Linphone
предложила RTP/SAVP, а endpoint 1003 был настроен на SAVPF. Это ошибка
настройки агента. У 1003 use_avpf исправлен на no; media_encryption=sdes
и обязательное шифрование сохранены. Публичный вход со старой учётки
Linphone сохраняет use_avpf=yes — клиент предлагает там другой профиль.
probe-echo.py подтвердил отдельный авторизованный вызов на Echo 600:
401 -> 100 -> 200, TLS 1.2, SRTP, BYE -> 200. Сотового вызова в этой
служебной проверке нет; наличие речи проверяется пользователем отдельно.
