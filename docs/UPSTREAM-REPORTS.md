# Gateway findings reported to maintainers

Reports filed and evidence checked on 24 November 2026. The links below distinguish individual project tickets, package reports and private product feedback. The [case index](INDEX.md) covers the symptoms, workarounds and limits.

## Asterisk and packaged builds

| Finding | Report and result |
| --- | --- |
| An incomplete Bluetooth audio frame followed by a nonblocking read error could terminate an active call. | [Asterisk #2336](https://github.com/asterisk/asterisk/issues/2336). The [standalone test](../recovery/2026-11-14/work/check-stock-sco-read.py) ran against three upstream releases and master. The [hardware observation](cases/sco-false-hangup.md) was on the 20.6.0 package. A maintainer placed the issue in the extended-support queue. |
| The tested Bluetooth transport used 48-byte host PCM blocks with a 60-byte on-air eSCO length. | Added measured framing, MTU bounds and the PCM regression test to [existing Asterisk #1664](https://github.com/asterisk/asterisk/issues/1664#issuecomment-7140141387). The same comment documents working incoming and outgoing iPhone MAP messages. The earlier proposal is closed. |
| The idle SCO listener polled about once per millisecond. | [Asterisk #2337](https://github.com/asterisk/asterisk/issues/2337). The [patch and tests](../research/idle-wakeups/README.md) reduced voluntary context switches on the listener thread from 981.34/s to 1.00/s. |
| The IAX2 trunk timer woke the network thread every 20 ms without a runtime trunk peer. | [Asterisk #2338](https://github.com/asterisk/asterisk/issues/2338). Arming the timer on the first peer and stopping it after the last one expired reduced that thread from 49.99 to 1.00 voluntary context switches/s. [Patch and tests](../research/idle-wakeups/README.md). |
| Outbound PJSIP MessageSend lost the charset explicitly provided in Content-Type. | [Asterisk #2339](https://github.com/asterisk/asterisk/issues/2339). A [loopback receiver](../research/message-content-type.md) saw the full value in an independent header, only the type/subtype in Content-Type and an intact body. |
| An SSRC change caused the distribution translator to discard decoded audio. | [Debian #1150408](https://bugs.debian.org/1150408) and [Ubuntu #2053070](https://bugs.launchpad.net/ubuntu/+source/asterisk/+bug/2053070) already cover the package patch. We shared the [reproducer and results](../research/rtp-source-reset.md) in [Asterisk #1324](https://github.com/asterisk/asterisk/issues/1324#issuecomment-7140548093). The stock Noble package produced 250/450 valid PCM frames. The same fixture with the workaround produced 450/450 and still dropped the late duplicate. |
| BASE64_ENCODE truncated the tail of a recipient URI at particular input lengths. | Already fixed upstream in [Asterisk #940](https://github.com/asterisk/asterisk/issues/940) and [PR #941](https://github.com/asterisk/asterisk/pull/941). The 20.6.0 and 20.10.0 sources have the old length calculation. Tag 20.11.0 includes the corrected allocation. The [gateway workaround](cases/agi-field-truncation.md) and byte-length regression tests remain relevant to older builds. |

For the two idle-wakeup proposals the maintainer [explained the contribution process](https://github.com/asterisk/asterisk/issues/2338#issuecomment-7140633475). The tickets are open. To accept code, the project requires a pull request and a signed contributor agreement. The public diffs and tests are available in the lab repository. The charset bug was triaged as core support.

## Network and gateway integration

- **Sagemcom F@ST 5670 port mappings.** On hardware 2.00, firmware SGFx10000381, a range of external UDP ports delivered to one internal port in LAN hairpin tests. Sixteen individual mappings preserved the ports. The [router case](cases/nat-rtp-range.md) identifies the three original probes, the working controls, and the separate SIP Contact configuration. It is a public field report specific to this firmware and topology.
- **Call setup and identity.** A registered Linphone account returned 488 until the endpoint matched its offered SAVP/SAVPF profile. The far-end phone received the caller number in SIP, but eight spaces in the display name hid it. Both cases include the working configuration and real-call observations. [SRTP profile](cases/linphone-srtp-profile.md) · [Caller ID](cases/caller-id-whitespace.md).
- **Address input.** One Linphone search attempt used an unexpected transport and another produced a leading colon. The saved evidence establishes a working input form. It does not connect that routing outcome to the display-code finding in #1055. [URI entry](cases/linphone-uri-input.md).
- **Dynamic DNS.** Our updater retained a stale AAAA record when the delegated prefix disappeared. The repaired updater clears it, restores the A record and distinguishes failed observation from a missing address. [Case and regression tests](cases/dns-stale-ipv6.md).
- **Message notifications and retries.** Seven notices appeared together after one outgoing request. Server timestamps identified checks and intermediate statuses sent at different times. The batching location remains unknown. The bridge now suppresses diagnostic chat notices and records submission before pushing to the handset, so an uncertain outcome does not trigger an automatic cellular retry. [Notification audit](cases/notification-burst.md) · [Queue and delivery](cases/iphone-map-outgoing.md).
- **Earlier web-phone experiment.** Desktop browser tests established WebSocket, SIP and media on a synthetic call. Captures from the physical iPhone placed its access failure before the local web server. The record keeps the unverified iOS background behavior and the tested Linphone route distinct. [WebRTC results](../STAGE1_WEBRTC_PWA_RESULTS.md) · [iOS access observations](../STAGE1_IOS_ACCESS_PAUSE.md).
