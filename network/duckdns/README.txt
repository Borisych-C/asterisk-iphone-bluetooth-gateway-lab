DuckDNS сервера .128 — исправление 14 ноября 2026, 18:05 IST

Имя home.example.net принадлежит серверу 192.168.50.10.
automation.example.net предназначено для .152 и этим изменением не затронуто.

Причина: прежний /usr/local/bin/duckdns-ip-update.sh при отсутствии IPv6
обновлял только IPv4, оставляя AAAA. На enp4s0 был только link-local адрес,
но DNS продолжал отдавать 2001:db8:1::10.
Принадлежность этого старого IPv6 какому-либо серверу не установлена.

Сохранены существующие duckdns-ip-update.service и timer: запуск после
загрузки и каждые 5 минут с добавочной случайной задержкой до 60 секунд.
Новых постоянно работающих процессов нет. Сервер/соседние службы не
перезапускались. Использован существующий проверенный shell-updater из
/home/gateway/HA/duckdns; копия адаптирована для .128, исходник HA не менялся.

Файлы на .128:
  /usr/local/bin/duckdns-ip-update.sh — копия update_duckdns.sh отсюда;
  /etc/duckdns-ip-update.conf — копия одноимённого файла, root:root 0600;
  /etc/letsencrypt/duckdns/home-example.token — прежний секрет, не менялся;
  /var/lib/duckdns-ip-update/last_ipv6 — последний подтверждённый IPv6;
  /var/lib/duckdns-ip-update/lock — запрет одновременных запусков.

Берётся только стабильный адрес 2000::/3 с работающего enp4s0. Адреса ULA,
temporary, deprecated, tentative и dadfailed не публикуются. При смене
префикса обновляются A и AAAA. При исчезновении IPv6 или отсутствии файла
состояния очищаются адресные записи, затем немедленно восстанавливается A.
DuckDNS не предоставляет отдельной операции удаления только AAAA:
https://www.duckdns.org/spec.jsp
Поэтому при очистке возможен короткий промежуток без A. IPv4 восстанавливается
даже после неопределённого результата запроса очистки; неудачная очистка
не подтверждается в состоянии и будет повторена следующим запуском.
При уже подтверждённом отсутствии IPv6 лишняя очистка A не выполняется.
Предполагается, что этот updater — единственный владелец адресных записей.
После ручной/сторонней записи AAAA при отсутствующем IPv6 удалить только
файл last_ipv6 и запустить службу: это принудительно сверит состояние.

Токен передаётся curl через stdin, без аргументов процесса и журналов.
HTTP-запросы ограничены по времени/размеру, временные ошибки повторяются
не более трёх раз. Файл состояния записывается атомарно только после успеха.

Проверки:
  python3 /home/gateway/asterisk/network/duckdns/test_updater.py
  bash -n /home/gateway/asterisk/network/duckdns/update_duckdns.sh
Пройдены 16 изолированных сценариев: наличие/смена/исчезновение IPv6,
непригодные адреса, ошибки API, тайм-ауты, восстановление IPv4 после ошибки
очистки и конкурирующий запуск. Реальный запуск службы завершился успешно.
Cloudflare 192.0.2.6 и Google 192.0.2.7: A=192.0.2.2, AAAA отсутствует,
ответ DNS NOERROR. Подробности dns-after.json и install-result.txt.
Реальное повторное появление префикса провайдера пока не проверено.

Восстановление после переустановки:
Сначала сравнить текущие файлы и сохранить резервную копию. При отсутствии
активного запуска обновления установить update_duckdns.sh как
/usr/local/bin/duckdns-ip-update.sh (root:root 0755), конфигурацию как
/etc/duckdns-ip-update.conf (root:root 0600), создать
/var/lib/duckdns-ip-update (root:root 0700). Прежний token-файл сохранить.
Не менять системные HOME/CODEX_HOME. Запустить:
  systemctl start duckdns-ip-update.service
  systemctl status duckdns-ip-update.timer
  journalctl -u duckdns-ip-update.service -n 15 --no-pager
Проверить A/AAAA через независимый DNS. Не восстанавливать прежний устаревший
IPv6 лишь ради совпадения со старым снимком.

Откат к прежнему алгоритму на .128 (возвращает исходную ошибку):
Сохранить новые файлы, остановить timer, убедиться, что service не активен,
вернуть скрипт из
/var/backups/duckdns-ip-update/20261114-180525/duckdns-ip-update.sh,
установить root:root 0755 и снова запустить timer. Новый конфиг/каталог
состояния старый скрипт не использует. Manifest в том же бэкапе содержит
исходные права и контрольную сумму. DNS-записи при откате не менять.
